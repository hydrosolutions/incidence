# Application validation: Zarafshan campaign, 1 October 2026

This historical record helps size an application and interpret replay guarantees. Reduced applications passed independent checks; the continuous 92-day full-basin application exhausted its execution budget. Passing reduced cases does not establish arbitrary network scalability.

The campaign used Incidence commit `665da4e0d81ab28921b8d5d2edbb9be27f4ec612` on macOS arm64, with Python 3.13 for Python applications. Integration versions and the native extension hash are in the [evidence excerpt](evidence/application-validation-2026-10-01.json). This records a pinned revision, not the behavior of future releases.

## What the applications establish

| Application | Tested scope and result |
|---|---|
| Connected networks | Chains of 4–64 reaches for three days; four-reach chain and five-reach split/reconfluence/storage motif through 365 days. Exact daily integer stock and conservation checks passed. |
| Native water/salt policies | Nine seven-day release policies plus fresh-model controls passed independent integer mixing checks. Equivalent held/fresh runs agreed; dry salt inventory remained accounted for. |
| Basin compilation | One application day with 61 semantic nodes/70 connections, compiled with observers to 287 finite compartments/465 connections. Direct Incidence and Taqsim canonical logs agreed; balances closed exactly. |
| Multiyear reservoir extractions | Two separate reservoirs reached 1,096 continuous days under baseline and synthetic drought/recovery scenarios. Twelve direct-native ladder cases passed exact policy checks and 2,434 prefix-row comparisons. |
| Prefix regeneration | Seven- and thirty-day native water/salt applications: ten valid prefixes reproduced canonical bytes and stocks. Six changed-model, corrupt-prefix or completed-log controls produced the expected refusal without mutating the prefix. |
| Resolution and isolation | Seventeen reservoir/use/return cases covered three joint water/mass resolutions and baseline/drought/saline scenarios. Five concurrent replicas, including simultaneous identical cases, matched serial scientific artifacts byte-for-byte. |

Independent reconstruction covered 7,107 compartment/substance/day stock checks across 24 controlled cells. A separate recovery review folded 346 native transfer records. The evidence excerpt retains these review fields and the source hashes. Counts overlap by purpose and are not a unique-test total.

The resolution campaign combines **native water execution with Taqsim physical transport** and Fishy assessment. Its chemistry checks should not be counted as additional native Incidence salt tests. Missing chemistry remained unknown. Separate-process isolation does not demonstrate thread safety, shared-file safety or optimizer multiworker support.

## Replay is not a checkpoint speedup

The recovery application used an audit-owned JSON codec and prefixes cut from completed reference runs. `resume_from_prefix` regenerated the whole execution and verified the supplied prefix. It did not test resumption after a real crash or saved computation from incremental restart. Its water schedule was externally precomputed; the delay compartment mixed salt rather than tracking parcel-specific salt delay. Users needing durable incremental checkpoints must evaluate that requirement separately.

## Full-basin performance remains unresolved

The continuous 92-day basin run timed out twice, after **7,200.133 and 7,200.267 seconds**. Build completed; native compiled execution had not returned. Neither attempt saved water results or exposed the simulated day reached. Seasonal conservation, temperature postprocessing and Fishy assessment therefore were not reached.

Sampled peak RSS was approximately 168 and 172 MiB, below the 2-GiB allowance. These are workload observations, not a performance SLA or complexity proof. [Issue #28](https://github.com/hydrosolutions/incidence/issues/28) tracks the repeated-ledger-replay concern. Smaller passing applications do not clear this failure; measure the intended topology, duration and result extraction workload before scheduling large ensembles.

## Evidence and limits

The JSON is a **selected evidence excerpt**, not a reproducible harness. It contains exact result/review fields, original file identifiers and hashes, and archive membership verified against retained campaign ZIPs. Those archives are held by the originating Zarafshan campaign and are not hosted in this repository; their hashes identify the handoff artifacts but are not download links.

Inputs include model-derived boundaries, synthetic policies and chemistry, and explicit quantization. No large real SWAT+ import, native thermal/biological physics or field calibration was established. This record adds application evidence, not complete feature coverage or a new execution run.
